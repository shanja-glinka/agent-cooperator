# Codex Workforce

**Два смешанных профиля. Законченные блоки работы. Ревью готового результата.**

[English](README.md) · [Профили](docs/profiles.md) · [Версия для Claude Code](docs/claude-code.md) · [Исследование](docs/research.md) · [Установка](docs/installation.md)

Агенты и skills для агентной разработки в двух средах из одного пакета:

- **Codex Workforce**: **GPT-6 Astra** отвечает за оркестрацию, сложные решения и
  приёмку, **GPT-5.5** выполняет основной объём реализации.
- **Claude Workforce**: те же роли для **Claude Code**: «мозг» на `opus`, исполнители
  на `sonnet`, разведка на `haiku`, ревью на `opus`, `fable` как резервный уровень.
  Подробности в [версии для Claude Code](docs/claude-code.md).

Пакет не требует GSD, отдельного сервера или нового менеджера задач.
Это независимый проект, не официальный продукт OpenAI или Anthropic.

## Установка и обновление

Нужны Node.js 22+, npm, Git и Codex с поддержкой пользовательских агентов,
явного выбора model/effort и доступом к обеим моделям.

```sh
# Codex
npx --yes github:shanja-glinka/codex-workforce install
npx --yes github:shanja-glinka/codex-workforce update
npx --yes github:shanja-glinka/codex-workforce status
npx --yes github:shanja-glinka/codex-workforce uninstall

# Claude Code: второй бинарник того же пакета
npx --yes -p github:shanja-glinka/codex-workforce claude-workforce install
npx --yes -p github:shanja-glinka/codex-workforce claude-workforce update
npx --yes -p github:shanja-glinka/codex-workforce claude-workforce status
npx --yes -p github:shanja-glinka/codex-workforce claude-workforce uninstall
```

Пакет запускается напрямую из публичного GitHub. Для фиксированной версии используйте
`github:shanja-glinka/codex-workforce#v1.1.0`. При обновлении фиксированной установки
укажите новый тег. После установки откройте новую сессию Codex.

`update` заменяет предыдущие файлы пакета и удаляет устаревшие файлы, которыми он
владеет. Чужие агенты, настройки и текст инструкций сохраняются. При конфликте
установщик сообщает конкретный путь. Подробности — в [контракте установки](docs/installation.md).

Можно сразу запустить Codex с реальными настройками выбранного профиля:

```sh
codex -p workforce-standard
codex -p workforce-enhanced
```

Названия продукта, ролей и команд не зависят от поколения моделей. Политика моделей
хранится в `profiles.json` и обновляется с версиями пакета; изменения описываются
в [журнале релизов](CHANGELOG.md).

## Как выбирается режим

Standard и Enhanced — необязательные ориентиры, а не закрытый список допустимых
схем. Выбор профиля задаёт предпочтение по подходу, но не закрепляет модели, effort
и состав команды. Агент может адаптировать их к задаче или использовать свою схему
без именованного профиля. Обязательны только отдельно заданные ограничения пользователя.

Конкретные, достаточно описанные поручения и небольшие исправления выполняются без
опроса: по умолчанию используется Standard. «Работай самостоятельно», «выбери сам»
и запуск без человека разрешают агенту выбрать Standard для понятного решения или
Enhanced для существенной неопределённости. Явный выбор и применимые постоянные
предпочтения учитываются; продолжения задачи и подагенты сохраняют выбранный режим.

Вопрос остаётся только перед длительной многоэтапной работой с существенными
неопределёнными решениями, когда профиль заметно влияет на подход или расход ресурсов,
а выбор ещё не задан и не делегирован. Важность продакшена, срочность и количество
шагов сами по себе не повод спрашивать. Даже при таком вопросе независимые уже
порученные действия, например создание и проверка резервных копий, продолжаются.

| Ответственность | Стандартный | Усиленный |
| --- | --- | --- |
| Оркестратор | Astra low | Astra high |
| Ограниченное исследование | GPT-5.5 medium | GPT-5.5 medium |
| Основная реализация | GPT-5.5 high | GPT-5.5 high |
| Неописанное сложное решение | Точечное подключение Astra | Отдельный блок Astra high |
| Ревью готового блока | GPT-5.5 xhigh | GPT-5.5 xhigh |
| Приёмка крупного этапа | Astra high | Astra high |

Стандартный подходит, когда решение достаточно описано. Усиленный — когда нужно
разобраться с неопределённой архитектурой или найти алгоритм. Даже сложный, но точно
описанный алгоритм может реализовывать GPT-5.5. Уровни Astra xhigh/max применяются
с объяснением причины, а не автоматически из-за длительности задачи.

**Текст инструкции не переключает модель текущего оркестратора.** Выберите Astra
и нужный effort средствами клиента. Агент обязан сообщать о несовпадении, а не
изображать переключение. Даже при явно выбранном профиле допустима адаптация без
нового согласования; явные строгие ограничения на модель,
effort и бюджет сохраняются. Установщик не переписывает `config.toml` и разрешения.

## Что изменяется в работе

- Один план и исходная цель пользователя; просьба проанализировать не разрешает правки.
- Исполнителю передаётся законченный результат с примером приёмки и границами владения.
- Исполнитель сам проверяет конвенции, документацию и поведение своего блока.
- Независимое ревью — после готового существенного блока, приёмка Astra — перед
  закрытием крупного этапа. Нет аудитора на каждую правку.
- Замена доказывается цепочкой: прежнее объявление → фактическая замена → потребители.
  Количество файлов и успешная сборка не подменяют результат.
- Исправления возвращаются владельцу одним пакетом; повторяются затронутые проверки.

Файлы хранятся в `CODEX_HOME` (по умолчанию `~/.codex`), а ссылки на skills — в
`~/.agents/skills`, откуда Codex их обнаруживает. Глобальная инструкция добавляется
отдельным управляемым блоком. Локальные копии в проекте могут иметь приоритет —
их миграция описана в документации.

## Версия для Claude Code

`claude-workforce` ставит аналог в `~/.claude` (или `CLAUDE_CONFIG_DIR` /
`--claude-home`): subagents `workforce-worker`, `workforce-probe`,
`workforce-reviewer`; skill `/workforce-orchestrate` со справочниками по маршрутизации
и инструментам; skills исполнителя, разведки, ревью и smoke; политику маршрутизации
и управляемый блок в пользовательском `CLAUDE.md`. Оба набора могут стоять на одной
машине: каждый владеет только своими файлами и маркерами. Набор включается
только по запросу: обычные сессии ничего не спавнят, оркестрация запускается
через `/workforce-orchestrate` или явную просьбу про workforce, subagents или
многоагентную работу.

Схема для Claude закрепляет то, что [исследование](docs/research.md) нашло в живых
конфигурациях: сначала классифицировать работу как `direct` / `build` / `pipeline`
и не запускать агентов на мелочь; «мозг» не пишет продуктовый код; модель задаётся
явно в каждом вызове Agent; исполнитель получает явный набор файлов и лимит ходов;
исправления возвращаются тому же исполнителю и тому же ревьюеру через SendMessage,
а не новому холодному агенту; ревью только на границе готового блока или этапа.

| Ответственность | Стандартный | Усиленный |
| --- | --- | --- |
| Мозг (ваша сессия) | `opus` medium | `opus` high |
| Ограниченное исследование | `haiku` medium | `sonnet` medium |
| Реализация | `sonnet` high | `sonnet` high, `opus` для нетривиальных блоков |
| Неописанное решение | точечно `opus` high | отдельный блок `fable` high (запасной `opus` xhigh) |
| Ревью блока | `opus` high | `opus` high |
| Приёмка этапа | `opus` high | `fable` high (запасной `opus` xhigh) |

Пакет не гарантирует идеального следования инструкциям или экономии токенов.
Стоимость оценивается по принятому результату и доступной телеметрии, с учётом
повторных попыток и исправлений. Тесты установщика не запускают платные модели.
