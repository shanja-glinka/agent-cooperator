# Codex Workforce и Claude Workforce

**Законченные блоки работы. Ревью готового результата. Объём, который не расползается.**

[English](README.md) · [Профили](docs/profiles.md) · [Версия для Claude Code](docs/claude-code.md) · [Исследование](docs/research.md) · [Установка](docs/installation.md) · [Изменения](CHANGELOG.md)

Небольшой, прозрачный набор агентов и skills для агентной разработки. Один пакет и
один установщик обслуживают две среды:

- **Codex Workforce**: **GPT-6 Astra** отвечает за оркестрацию, сложные решения и
  приёмку, **GPT-5.5** выполняет основной объём реализации.
- **Claude Workforce**: те же роли для **Claude Code**: «мозг» на `opus`, исполнители
  на `sonnet`, разведка на `haiku`, ревью на `opus`, `fable` как резервный уровень.

У обеих версий один воркфлоу: оркестратор сначала читает правила самого репозитория,
выдаёт исполнителям законченные блоки с зафиксированным объёмом, возвращает правки
тем же исполнителю и ревьюеру, проверяет только готовые блоки, а находки за пределами
поручения отдаёт пользователю как follow-up, а не превращает в новую работу.
Standard для достаточно описанного решения, Enhanced, когда решение ещё нужно найти.

Пакет не требует GSD, отдельного сервера или нового менеджера задач. Это набор
инструкций с установщиком на Node.js, а не гарантия поведения моделей или экономии.
Независимый проект, не официальный продукт OpenAI или Anthropic.

## Установка и обновление

Нужны Node.js 22+, npm и Git. Пакет запускается напрямую из GitHub, публикация в
npm не требуется. В пакете два бинарника.

```sh
# Codex (бинарник по умолчанию, совпадает с именем пакета)
npx --yes github:shanja-glinka/codex-workforce install
npx --yes github:shanja-glinka/codex-workforce update
npx --yes github:shanja-glinka/codex-workforce status
npx --yes github:shanja-glinka/codex-workforce uninstall

# Claude Code (второй бинарник, выбирается через -p)
npx --yes -p github:shanja-glinka/codex-workforce claude-workforce install
npx --yes -p github:shanja-glinka/codex-workforce claude-workforce update
npx --yes -p github:shanja-glinka/codex-workforce claude-workforce status
npx --yes -p github:shanja-glinka/codex-workforce claude-workforce uninstall
```

`update` заменяет предыдущие файлы пакета и удаляет устаревшие файлы, которыми он
владеет. `status` показывает дрейф. `uninstall` удаляет только своё. Для
фиксированной версии используйте `github:shanja-glinka/codex-workforce#v1.1.0` или
проверенный SHA коммита. После установки откройте новую сессию Codex или Claude Code.
Оба набора могут стоять на одной машине: у каждого свои файлы, состояние и маркеры.

Общие опции: `--dry-run`, `--force` (резервная копия и замена отредактированных
своих файлов), `--json`. Codex: `--codex-home PATH` (приоритет: опция, `CODEX_HOME`,
`~/.codex`) и `--skills-dir PATH` для ссылок в `~/.agents/skills`. Claude Code:
`--claude-home PATH` (приоритет: опция, `CLAUDE_CONFIG_DIR`, `~/.claude`); skills
обнаруживаются внутри этой директории, поэтому `--skills-dir` нет. Установщик не
трогает `config.toml`, `settings.json`, модели по умолчанию и разрешения.

## Версия для Codex

Роли `workforce_probe`, `workforce_worker`, `workforce_reviewer` (TOML без модели),
пять skills, два необязательных слоя запуска и управляемый блок в глобальном
`AGENTS.md`:

```sh
codex -p workforce-standard
codex -p workforce-enhanced
```

| Ответственность | Стандартный | Усиленный |
| --- | --- | --- |
| Оркестратор | Astra low | Astra high |
| Ограниченное исследование | GPT-5.5 medium | GPT-5.5 medium |
| Основная реализация | GPT-5.5 high | GPT-5.5 high |
| Неописанное сложное решение | Точечное подключение Astra | Отдельный блок Astra high |
| Ревью готового блока | GPT-5.5 xhigh | GPT-5.5 xhigh |
| Приёмка крупного этапа | Astra high | Astra high |

Конкретные поручения выполняются без опроса. «Работай самостоятельно» разрешает
агенту выбрать профиль. Вопрос остаётся только перед длительной многоэтапной
работой с существенными неопределёнными решениями, если выбор не задан и не
делегирован. Можно написать **«Используй Enhanced»**; исполнители наследуют выбор.
Подробности в [правилах выбора](docs/profiles.md).

Профили — необязательные ориентиры; своя схема допустима и после выбора профиля.
Обязательны только отдельно заданные ограничения на модель, effort и бюджет.
**Текст инструкции не переключает модель текущего оркестратора.** Выберите Astra и
effort средствами клиента; агент обязан сообщать о несовпадении.

## Версия для Claude Code

Subagents `workforce-worker`, `workforce-probe`, `workforce-reviewer` (Markdown-роли
с `model: inherit`, `effort`, `maxTurns`, без права спавнить детей), skill
`/workforce-orchestrate` со справочниками по маршрутизации и инструментам, skills
исполнителя, разведки, ревью и smoke, политика маршрутизации и управляемый блок в
пользовательском `CLAUDE.md`. Подробности в [версии для Claude Code](docs/claude-code.md).

Набор включается только по запросу. Обычные сессии ничего не спавнят: оркестрация
запускается через `/workforce-orchestrate`, явную просьбу про workforce, subagents
или многоагентную работу, либо по требованию инструкций проекта. Внутри набора
работа сначала классифицируется: `direct` выполняется инлайн без агентов, `build`
получает одного исполнителя и одно ревью готового диффа, `pipeline` — план,
параллельных исполнителей с непересекающимися наборами файлов, ревью блоков и
приёмку этапа.

| Ответственность | Стандартный | Усиленный |
| --- | --- | --- |
| Мозг (ваша сессия) | `opus` medium | `opus` high |
| Ограниченное исследование | `haiku` medium | `sonnet` medium |
| Реализация | `sonnet` high | `sonnet` high, `opus` для нетривиальных блоков |
| Неописанное решение | точечно `opus` high | отдельный блок `fable` high (запасной `opus` xhigh) |
| Ревью блока | `opus` high | `opus` high |
| Приёмка этапа | `opus` high | `fable` high (запасной `opus` xhigh) |

Модель задаётся явно в каждом вызове Agent; effort берётся из frontmatter роли или
сессии. Правки идут тем же исполнителю и ревьюеру через SendMessage; новый агент
нужен только для независимости, другого уровня модели или загрязнённого контекста.

## Как идёт работа (обе версии)

1. Прочитать правила репозитория (`AGENTS.md`, `CLAUDE.md`, `.claude/rules/`,
   `CONTRIBUTING.md`) и передать их каждому подагенту как PROJECT_RULES; они
   главнее набора.
2. Один раз выбрать профиль; классифицировать работу до запуска кого-либо.
3. Согласовать реальный результат и пример приёмки. «Проанализируй» остаётся анализом.
4. Выдать законченные блоки с владением, точными источниками, зафиксированными
   SCOPE и OUT_OF_SCOPE. Дизайн-решения принимаются до брифа, а не делегируются в нём.
5. Исполнитель реализует, подключает потребителей, сам проверяет весь результат и
   перечисляет наблюдения вне объёма как follow-up, не реализуя их.
6. Независимое ревью готового существенного блока по диффу. Находки помечаются
   in-scope, follow-up или behavior-change; к тому же исполнителю возвращаются только
   in-scope, а отклонение ранее принимаемого ввода требует решения пользователя.
7. Отдельный ревьюер принимает крупный этап по исходной цели и обязательным
   проверкам пакета. Ничего не считается готовым без проверки end-to-end.

Нет аудитора на каждую правку, нет обязательного разветвления для мелочей, нет
нового ревьюера после каждого исправления. Инвентарь, сгенерированная заготовка или
зелёная сборка не заменяют результат. Строки changelog описывают только видимое
пользователю поведение.

## Что устанавливается

| | Codex (`CODEX_HOME`, по умолчанию `~/.codex`) | Claude Code (`~/.claude`) |
| --- | --- | --- |
| Роли | `agents/workforce_*.toml` | `agents/workforce-*.md` |
| Skills | `skills/workforce-*/` со ссылками в `~/.agents/skills` | `skills/workforce-*/` |
| Слои запуска | `workforce-standard.config.toml`, `workforce-enhanced.config.toml` | нет |
| Политика и манифест | `codex-workforce/profiles.json`, `manifest.json` | `claude-workforce/profiles.json`, `manifest.json` |
| Инструкции | блок в `AGENTS.md` (или активном `AGENTS.override.md`) | блок в `CLAUDE.md` |

Локальные агенты, skills и инструкции проекта могут иметь приоритет; подробности в
[контракте установки](docs/installation.md).

Пакет не гарантирует идеального следования инструкциям или экономии токенов.
Стоимость оценивается по принятому результату и доступной телеметрии. Тесты
установщика не запускают платные модели; версия для Claude дополнительно проверена
на тестовом репозитории, прогоны описаны в [документации](docs/claude-code.md).
