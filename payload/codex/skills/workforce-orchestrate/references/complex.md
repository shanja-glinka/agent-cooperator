# Complex routing (Codex)

Load this reference when the user explicitly selects Complex, or when no task
or launch profile, active choice, or applicable standing preference applies
and a genuinely difficult delegated block may justify it. Explicit Economy,
Standard, `codex-workforce-owner`, and strict model, effort, or budget limits
take precedence. The owner command keeps its selected Sol author route.

Choose by acceptance boundary first. Complex is for difficult independently
delegated work with interacting constraints, complex concurrency, long tracing,
or bounded design decisions. Large mechanical volume alone does not qualify.
A connected deliverable whose semantics are accepted only on combined behavior
stays with the Sol cooperator for authorship and its connected-owner review.
Ordinary independent blocks use the selected Economy or Standard Luna route.

For each Complex worker block, spawn GPT-6.2 Sol with one explicit effort:

- `low`: exact, fully specified edit with no unresolved design or tracing;
- `medium`: bounded design or tracing inside one clear write set;
- `high`: interacting constraints or complex concurrency.

Choose effort independently per block. Blocks in one job may use different
efforts. Never use `xhigh` automatically. If a block needs a different effort,
handoff to a fresh Sol thread at that effort with the original packet, current
snapshot, APPROACH, and HANDOFF; preserve attempts, tokens, and tool calls.
Complex workers have three attempts and a 500k token ceiling. At Sol's limit,
re-plan or ask the user; there is no higher tier or automatic xhigh step.

When `reviewBlock` is on, every submitted Complex worker block, including one
written by Sol, receives an independent Sol review at the effort chosen for the
contract. With it off, use required checks and your own whole-diff reading,
unless the user, project, task, or another route requires review. `reviewStage`
applies only to an integration part no block review covered. A review that has
already read the final diff and interactions satisfies the same duty; do not
duplicate it.

Do not infer actual runtime identity from this instruction. Set the model and
effort on each spawn and report material runtime mismatches honestly.
